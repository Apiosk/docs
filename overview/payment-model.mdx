---
title: "Prices and balance"
description: "What buyers see, approve, and are charged."
---

Apiosk shows a price before a data purchase. The displayed total is the most
the request may cost. You approve that ceiling once; the finished run reports
the actual charge and the source behind it.

## The buying flow

1. Browse sources or ask a question. Browsing and planning are free.
2. Review the plan and its total price ceiling.
3. Approve the plan in the app or MCP card. With the API, send
   <code>max_spend</code> to authorize an automatic run or call the plan's run
   endpoint.
4. Apiosk reserves each source call before dispatching it. Settled charges and
   any funds still held appear separately in the run's <code>usage</code>.
5. Read the sourced result and final charge. Unused reserved money is released.
   A call that did not deliver data is refunded or held for reconciliation if
   its outcome is still unknown.

Prices and balances are shown in USD. API amounts include both a decimal
<code>amount</code> and an exact <code>amount_micro_usd</code>. The catalogue's
price is the buyer total for that operation; there is no extra fee to add to
the displayed quote.

## Which balance pays?

| Caller | Balance |
| --- | --- |
| Organisation API key | The organisation's main balance |
| Person in a workspace | That workspace's budget |
| Person outside a workspace | Their personal balance |
| Assistant connection | The balance of the person or workspace that approved it |

An API key also has its own per-request and monthly limits. An assistant
connection has a per-request and daily limit. A limit or balance refusal means
the purchase did not start. In the buyer API, HTTP 402 with
<code>insufficient_balance</code> or <code>spend_limit_exceeded</code> asks you
to fund the balance or change the relevant limit.

For exact fields, see [Balance and usage](/api/billing),
[Ask](/api/ask), and [Runs](/api/runs).
